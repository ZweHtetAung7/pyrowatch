DOCUMENT PURPOSE
----------------
Use this file as repository-specific implementation context. It records the
current code shape, data flow, contracts, build/run commands, and verified
scope boundaries so a follow-on AI can make changes without rediscovering the
whole system or inventing unsupported behavior.

This is a source-oriented handoff, not a product pitch. Source code is
authoritative when this file and the repository disagree. Do not infer that a
requested feature exists just because it was discussed in chat or is described
as a future improvement below.

-----------

2. Keep changes scoped to the user's requested behavior. Update tests and
   directly related documentation when behavior or public contracts change.

   In particular, preserve wildfire fields in /api/risk, the ESP32 /api/beacon

   to discover variable names. Never place secrets in source or documentation.

   Treat all heuristic scores as indices, not probabilities or official

7. Verify a requirement directly. Syntax checks alone do not prove runtime

CURRENT FEATURE BOUNDARY — READ BEFORE MULTI-HAZARD CHANGES
----------------------------------------------------------
Implemented in the inspected source:
  - Wildfire relative risk index, Fosberg fire weather index, optional trained
    seven-day fire-detection classifier.
  - Experimental thunderstorm index based on 48-hour CAPE.
  - Experimental blizzard index based on snowfall, gusts, and temperature.

These are source-confirmed gaps, not proposals already applied. If asked to

SYSTEM BOUNDARY AND RUNTIME
---------------------------
Runtime topology:

  Browser
    - index.html, app.js, hazards.js, style.css
    - Leaflet map and checked-in Leaflet/satellite.js browser libraries
    - calls same-origin /api/* endpoints using fetch()
    - calculates animated satellite tracks and pass estimates in browser

  One FastAPI/Uvicorn process
    - serves API and frontend assets
    - computes statewide cell scores on demand
    - caches provider results in process memory; some immutable/replay inputs
      use local JSON caches
    - optional AI calls to Gemini and ElevenLabs
    - optional PostgreSQL/TimescaleDB writes and history reads
    - receives ESP32 beacon status requests and sensor POSTs

  External inputs
    - NASA FIRMS: VIIRS/MODIS active fire observations and historical data
    - Open-Meteo: forecast/archive daily weather, hourly CAPE/snowfall,
      elevation
    - NASA MODIS via ORNL DAAC: vegetation NDVI fetched by script
    - CelesTrak: orbital elements (TLE)
    - Esri: browser basemap tiles
    - Gemini: briefings and tool-using Q&A when configured
    - ElevenLabs: speech audio when configured
    - PostgreSQL/Tiger Data: optional persistence

  ESP32 PyroWatch Beacon
    - independently polls GET /api/beacon
    - can POST sensor readings to /api/stations/{station_id}
    - is not built or deployed by the Python service

There are no independently deployed backend services in the checked-in
topology. Do not assume a broker, scheduler, Redis, separate frontend host,
authentication gateway, or container orchestration layer.

SOURCE-OF-TRUTH MODULE MAP
-------------------------
backend/main.py
  FastAPI app, route declarations, HTTP input validation, status/config
  response assembly, Pydantic request bodies, beacon payload, and root static
  mount. This is the composition layer, not a standalone typed service layer.

backend/risk.py
  Feature aggregation and derivation, fire-risk factor scoring, FFWI, severe
  weather screening indices, optional classifier inference, result assembly,
  active fire retrieval composition, daily ledger snapshot, and historical
  fire validation. This is the primary scoring and forecast-domain module.

backend/sources.py
  Provider adapters, HTTP client, retry logic for selected requests, per-source
  fallback policy, TTL memory cache, historical weather disk cache, elevation
  cache, fire CSV parsing/filtering, and TLE retrieval. Provider status is part
  of returned data and propagated into API/UI source badges.

  Simplified California boundary, place list, point-in-polygon and polygon
  clipping, default 0.5-degree grid construction, cell identity/index mapping,
  and geographic distance/direction utilities. Grid cell identity is derived
  from row/column and configured grid step.

backend/demo.py
  Deterministic synthetic provider data: daily weather, hourly CAPE/snowfall,

  conditions or model skill.

DATA FLOW AND SCORING CONTRACT
------------------------------
1. /api/risk parses `as_of` and calls risk.compute_risk(date | None).
   `None` means the current local date in America/Los_Angeles. Future dates are
   rejected. Historical dates are allowed down to the fire-data era.
2. risk._cell_inputs builds cells via geo.build_grid(), fetches daily weather
   from `as_of - 31 days` through `as_of + 1 day`, fetches elevation samples,
   loads fire history/vegetation, and creates per-cell features.
3. sources.get_weather uses Open-Meteo forecast API for recent/current ranges
   and archive API for older ranges. Daily calls contain the ordinary weather
   variables; an additional hourly request asks for `cape` and `snowfall` over
   the scoring window. Hourly values are aggregated by local date into:
     cape_max_jkg: maximum hourly CAPE per date, J/kg.
     snowfall_sum_cm: sum hourly snowfall per date, cm.
   risk.raw_features selects the maximum CAPE and adds the daily snowfall
   totals for `as_of` and `as_of + 1`. If hourly values are missing, resulting
   hazard measurements/scores can be null; do not reinterpret missing as zero.
4. Fire fuel antecedent features use dates strictly before as_of:
   precipitation in prior 30 days, rain-day recency, VPD. Fire history uses
   the preceding five calendar years, excluding as_of year.
5. Each cell receives the existing wildfire weighted index:
     FACTORS:
       fuel dryness 0.30
       wind         0.20
       low humidity 0.18
       fire history 0.14
       heat         0.10
       terrain      0.08
     for each available factor:
       points = 100 * factor_weight / available_weight_sum
                * factor_value * fuel_gate * vegetation_gate
       wildfire risk = sum(points)
     fuel_gate = 0.35 + 0.65 * fuel_dryness (if unavailable, dryness fallback
     in gate uses 0.5).
     vegetation_gate = 0.2 + 0.8 * clamp01((NDVI - 0.10) / 0.30);
     if NDVI is missing, vegetation_gate is 1.0.
   Factor transforms are implemented in risk.score_factors; preserve them if
   changing presentation or adding hazards. Missing factor weights are
   redistributed among available factors. The weighted index is not a
   probability.
6. risk.fosberg_ffwi computes a 0–100 weather-only Fosberg index from high
   temperature, low relative humidity, and max sustained wind. It is included
   in raw features, the UI/agent context, and fire validation baseline.
7. Current additional experimental hazard indices:
     Thunderstorm:
       score = round(100 * clamp01(cape_max_jkg / 2500), 1)
       It has one factor (Peak CAPE, weight 1.0). No wind component is present.
       None is returned when CAPE is unavailable.
     Blizzard:
       raw snowfall component = clamp01(snowfall_48h_cm / 25), weight 0.60.
       raw wind component = clamp01((gust_kmh - 25) / 55), weight 0.25.
       raw cold component = clamp01((5 - tmax_c) / 20), weight 0.15.
       Available factor weights are renormalized. All component points are
       multiplied by snowfall_gate = clamp01(snowfall_48h_cm / 15).
       No score if no factors are available. With snowfall 0, the resulting
       score is 0 even if wind/cold are severe. This is a screening heuristic,
       not a meteorological blizzard warning.
   Both use shared category thresholds:
       score >=75 Extreme; >=60 Very high; >=40 High; >=20 Moderate; else Low.
8. The optional classifier bundle is loaded from data/model.joblib when present.
   Bundle contains model, feature order, and metrics. Inference uses stored
   bundle feature names when available so older bundles can remain compatible.
   Current model target is a new FIRMS fire detection in the same grid cell
   within seven days; it is not a calibrated all-hazard probability.
9. Risk results are cached through sources._cached: current/recent risk uses
   30-minute TTL; old replay results use 24 hours. Individual provider
   functions also have their own TTL/disk caching.
10. Live current-date risk writes to the optional database in background.
    Optional JSON ledger records first prediction per date only if configured.

GRID AND GEOSPATIAL INVARIANTS
-----------------------------
Default spatial extent is California:
  bbox west=-124.5, south=32.5, east=-114.0, north=42.1.
  simplified outline polygon in backend/geo.py.
  default grid_step=0.5 degrees.
  IDs are `r{row:02d}c{column:02d}`, row/column based from south/west.
  Cells with fewer than three land samples or a clipped polygon under three
  vertices are skipped.
  Weather query point is the mean of on-land samples, snapped to nearest land
  sample if a concave cell mean lies outside California.
  Terrain samples are chosen from land points in the cell.
  `cell_for_point` maps the coordinate to the row/column cell index; outside or
  skipped cells return None.
  `shape` is a Leaflet-ready array of [latitude, longitude] polygon vertices.

Grid step changes cell IDs, cell count, static dataset validity, map search,
station associations, historical fire data, and model feature training. Data
files carry `meta.grid_step`; consumers check for matching grid step in
several paths. Do not change GRID_STEP without rebuilding/revalidating
fire_history.json, fire_days.json, vegetation.json, model.joblib, ledger data,
and any stored cell-keyed records.

API CONTRACTS
-------------
All endpoints are defined in backend/main.py. FastAPI auto-publishes schema
docs at /docs; there is no separately maintained OpenAPI file. Only request
bodies have explicit Pydantic models (AskBody, Reading); most responses are
ordinary Python dict/list objects rather than typed response models.

GET /api/config
  Returns data_mode, today, grid_step_deg, key-presence booleans, selected
  Gemini model, TTS/agent flags, model presence, DB status, replay_presets,
  places, grid origin/step, wildfire factors, hazard metadata.

GET /api/risk?as_of=YYYY-MM-DD
  Global result keys:
    as_of, window, is_live, generated_at, model, hazards,
    counts_by_hazard, top_by_hazard, sources, counts, top, cells.
  `hazards` is metadata keyed exactly by wildfire/thunderstorm/blizzard.
  `counts_by_hazard[hazard]` maps shared category name to count.
  `top_by_hazard[hazard]` contains up to eight {id,name,score,category}.
  Cell keys include:
    id, name, lat, lon, shape, risk, category, fuel_gate, veg_gate,
    vegetation, factors, hazards, raw, rank, optional ml_prob.
  `risk`, `category`, `factors`, and `rank` remain the wildfire contract.
  `hazards` maps:
    wildfire -> {score, category, factors}
    thunderstorm -> {score|null, category|null, factors, optional rank}
    blizzard -> {score|null, category|null, factors, optional rank}
  Factor rows include key, label, weight, normalized value, points and explain
  for wildfire; severe factor rows include key/label/weight/value/points/
  explain. `raw` includes source-derived features, including FFWI,
  cape_max_jkg, snowfall_48h_cm; month_sin/month_cos are excluded.
  No `primary_hazard` key currently exists.

GET /api/fires?as_of=&days=2
  days constrained 1..10. Returns as_of, days, source status, count and
  detections. Current `as_of=None` is recent live window; replay uses the
  specified start date.

GET /api/validate?as_of=&top_fraction=0.2
  top_fraction strictly between zero and one. Compares forecast/risk ranking
  with FIRMS detections in a window up to three days; uses the recorded
  snapshot if available, otherwise a hindcast. Returns significant-fire
  metrics, all-hotspot metrics, Fosberg baseline metrics, methods, sources,
  rules, caveats, and cells. It evaluates wildfire rank only.

GET /api/satellites
  Returns source status and satellite array with name/NORAD/instrument/swath/
  TLE values (synthetic flag may be included in demo).

GET /api/briefing/{cell_id}?as_of=&hazard=wildfire
  hazard must be one of the three keys in risk.HAZARDS or returns HTTP 400.
  Returns {engine,text}, optional error. The text is plain text; the model is
  asked for a short score-and-measurement briefing with two action bullets.

POST /api/ask
  AskBody {question:string, cell_id?:string|null, as_of?:string|null}.
  Returns engine, text, steps (tool trace), areas (touched cell IDs). The
  agent supports wildfire-oriented tools; it is not currently hazard-select
  aware.

GET /api/tts/{cell_id}?as_of=&hazard=wildfire
  Returns audio/mpeg when configured; 404 if ElevenLabs key absent; 502 when
  provider request fails.

GET /api/history/{cell_id}?days=14
  days constrained 1..365. DB-backed hourly risk aggregate and daily fire
  counts; returns enabled/timescale/days/risk/fires. It aggregates only the
  legacy wildfire `risk` numeric column.

GET /api/beacon?lat=<float>&lon=<float>&radius_km=50
  radius constrained 5..300 km. Returns 404 if location is not in the
  California cell index. Existing firmware depends on:
    area, cell_id, risk, category, level, rank, of, fires_nearby, radius_km,
    nearest_fire_km, latest_fire_utc, top_factor, as_of, generated_at, demo.
  `level` is index in ["Low","Moderate","High","Very high","Extreme"].
  Current code additionally returns `hazards` keyed by existing hazard name,
  values {score, category}. Firmware still consumes wildfire risk/level only.
  Preserve old fields and their types if adding primary-hazard output.

POST /api/stations/{station_id}
  Reading {lat,lon,temp_c?,rh_pct?,smoke_raw?,label?}. If server STATION_TOKEN
  is non-empty, request header X-Station-Token must match. Returns station
  summary; invalid values return 422 and invalid token 401.

GET /api/stations?max_age_hours=24
  max_age_hours constrained >0 and <=720; returns in-memory active station
  summaries, most recent first.

GET /api/stations/{station_id}/history
  Returns recent in-process history (up to 240 default) or 404 for unknown
  station.

GET /api/health
  Returns {"ok":true}; liveness only, not a readiness/provider/DB check.

GET /
  StaticFiles mount serving frontend/index.html and assets.

DATABASE CONTRACT AND LIMITATIONS
---------------------------------
backend/store.py supports optional PostgreSQL. If DATABASE_URL is empty,
database methods return no-op/empty shapes. If configured, current create
schema has:

  risk_predictions(
    recorded_at timestamptz NOT NULL,
    as_of date NOT NULL,
    cell_id text NOT NULL,
    risk real NOT NULL,
    category text NOT NULL,
    ml_prob real NULL,
    gust_kmh real NULL,
    rh_min_pct real NULL,
    days_since_rain real NULL,
    thunderstorm_score real NULL,
    blizzard_score real NULL,
    PRIMARY KEY(cell_id, recorded_at)
  )

  fire_detections(
    time timestamptz NOT NULL,
    lat double precision NOT NULL,
    lon double precision NOT NULL,
    cell_id text NULL,
    satellite text NOT NULL,
    instrument text NULL,
    confidence text NULL,
    frp real NULL,
    source text NULL,
    PRIMARY KEY(time, lat, lon, satellite)
  )

  ground_readings(
    time timestamptz NOT NULL,
    station_id text NOT NULL,
    lat double precision NOT NULL,
    lon double precision NOT NULL,
    temp_c real NULL,
    rh_pct real NULL,
    smoke_raw real NULL,
    PRIMARY KEY(station_id, time)
  )

Indexes:
  risk_predictions_asof(as_of, recorded_at)
  fire_detections_cell(cell_id, time DESC)

MIGRATIONS currently add nullable `thunderstorm_score` and `blizzard_score`
with `ADD COLUMN IF NOT EXISTS`. SCHEMA is run before MIGRATIONS on DB
initialization. Timescale extension/hypertables are attempted after schema;
exception in this optional step marks plain PostgreSQL mode.

`record_prediction` persists legacy wildfire risk/category, optional ml_prob,
gust/rh/rain fields and the thunderstorm/blizzard scores using named INSERT
columns. It does not persist CAPE, snowfall, per-hazard factors/categories,
or a primary hazard. `recorded_prediction` reads wildfire fields only.
`cell_history` aggregates wildfire risk only.

DB operational behavior:
  - one module-global connection/state, guarded by threading.Lock;
  - psycopg imported only upon first DB connection attempt;
  - autocommit enabled;
  - connection failures mark DB unavailable for RETRY_AFTER_S=60 seconds;
  - query/write exceptions are logged, connection closed, and operation
    returns None;
  - writes launched by daemon threads; thread exceptions are not joined at app
    shutdown;
  - no ORM or migration framework; schema is source-defined SQL.

The station registry/history is in process memory despite optional
ground_readings persistence. A restart loses active station labels/locations/
history until stations report again. DB history APIs do not rebuild this map.

AI BRIEFINGS AND Q&A
--------------------
Briefing:
  main.get_briefing validates selected hazard and cell, computes risk, counts
  fires in cell, calls ai.briefing.
  ai._cell_context currently passes selected hazard score/category/factors,
  every hazard score, wildfire context, FFWI, ml_prob, weather/source context,
  and neighboring area values. It does not expose a primary_hazard field
  because risk results do not define one.
  Gemini receives prompt instructions and JSON context; output is not schema
  constrained or parsed as JSON. It is plain text.
  On Gemini failure/missing key, _template_briefing provides deterministic
  hazard-specific text/action bullets. Briefing result is cached in process by
  date, cell, wildfire risk, fire count and hazard.
  Safety semantics: scores are relative indexes; CAPE is instability not
  storm occurrence; snow/wind/temp do not imply official blizzard warning;
  synthetic sources must be disclosed.

Q&A agent:
  agent.Tools builds one risk result on initialization and lazily loads fires.
  Place resolution supports cell ID, known place name/substring, coordinates,
  or near-boundary nearest cell up to 60 km.
  Eight tool names in agent.py:
    find_area, top_areas, compare_areas, fires_near, satellite_passes,
    statewide_summary, validation, ground_stations.
  Gemini can make up to MAX_STEPS=6 tool rounds. Tool calls/results and touched
  cell IDs are returned for UI trace/highlighting.
  Without Gemini key, `_offline` chooses tools via a small keyword router.
  Current tools/agent instructions focus on wildfire; multi-hazard reasoning
  is not implemented despite multi-hazard map/briefing support.

External Gemini model selection is dynamic:
  config default is `gemini-3.7-flash`;
  ai.available_models queries models endpoint and sorts Flash models;
  retryable model errors include 404, 429, 500, 503 and timeout;
  at most four models tried within a total time budget;
  selected fallback is retained in process;
  actual successful live model behavior requires key/network and is not
  validated by unit tests.

DEMO, PROVIDER AND CACHE SEMANTICS
---------------------------------
`DATA_MODE` behavior:
  demo: bypass live service calls for sources with synthetic implementation.
  auto: attempt live then substitute synthetic data independently by source.
  live: let live-service errors surface; missing FIRMS key is an explicit
        error for fire retrieval in live mode.

Every source getter generally returns (data, status). Status carries at least
source and mode (`live`, `demo`, or `off`), sometimes note/composite/years.
Frontend uses this metadata to show per-source badges and aggregate DEMO DATA.
Historical cached weather is labeled live/cached by source logic; it is not a
fresh current forecast.

Cache behavior:
  - process-local dict + per-key threading lock in sources.py;
  - weather memory TTL: 30 minutes near present, 7 days for older range;
  - old weather JSON disk cache for historical periods;
  - elevation cache in data/cache/elevation.json, updated by batches;
  - fire retrieval TTL: 15 minutes near present, 24 hours old dates;
  - TLE TTL: 4 hours;
  - risk TTL: 30 minutes recent, 24 hours historical;
  - briefing cache process-local;
  - model loaded/cached by model file mtime.
No shared cache or cross-worker cache invalidation exists.

FIRE DETECTION AND VALIDATION SEMANTICS
---------------------------------------
FIRMS CSV parser:
  - keep points inside California outline;
  - exclude `type` labels 1, 2, 3 (volcano, static industrial source, offshore);
  - convert acquisition date/time to UTC;
  - translate VIIRS confidence letters and MODIS numeric confidence;
  - normal/minimum confidence setting defaults to nominal, retaining nominal,
    high, and unknown.
NRT products selected for recent requests; archive products used for dates at
least 60 days old, with fallback to NRT if archive returns no detections.
Product-level failures are tolerated unless all requested product requests
failed.

Validation:
  - default date is two days before today;
  - uses earliest recorded prediction in PostgreSQL or date ledger, otherwise
    recomputes a hindcast using observed historical weather;
  - future fire window up to three days (bounded by current date);
  - recent prior detections in five-day lookback help avoid counting ongoing
    fire/hotspot cells as newly ignited;
  - "significant": at least 2 detections and maximum FRP >=50 MW;
  - top_fraction default 0.2; hit rate, lift over random and pairwise ROC AUC;
  - all-hotspot metrics also reported;
  - comparison baseline ranks by FFWI.
This is a spatial/ranking sanity check with imperfect satellite labels, not
prospective operational validation. Keep the method string and synthetic
source disclosures visible.

MODEL TRAINING AND DATA LINEAGE
-------------------------------
Training script:
  - creates one row per cell and weekly season sample date;
  - features use `risk.raw_features`, including weather, FFWI, vegetation,
    fire history, and annual seasonality;
  - label uses FIRMS per-cell fire dates: any detection in next 7 days and
    none in prior 5 days; demo mode uses synthetic fires for pipeline tests;
  - time split by year: max requested year is test; earlier years are train;
  - fits logistic regression pipeline (impute, standardize, class-balanced)
    and HistGradientBoosting classifier;
  - compares weighted score and Fosberg baseline by ROC AUC and PR AUC;
  - selects model with best ROC AUC; writes model.joblib with feature order
    and metrics and model_metrics.json with full results.

Committed model_metrics.json currently describes a real FIRMS+ERA5 evaluation:
  chosen model logistic_regression, test year 2023, train years 2021/2022,
  10,044 samples, 611 positives, 7.17% base rate,
  ROC AUC 0.701 / PR AUC 0.140; weighted baseline ROC AUC 0.609.
These are artifact-reported historical results; they are not independently
recomputed by updating this architecture document and should not be described
as current multi-hazard validation. Adding hazard features would need separate
labels, target definitions and evaluation rather than reusing wildfire labels.

DEVICE CONTRACT AND NON-OBVIOUS LIMITS
--------------------------------------
ESP32 polls /api/beacon every POLL_SECONDS (example 60 sec), reading only the
legacy wildfire fields:
  risk, level, area, rank, of, fires_nearby, nearest_fire_km, top_factor, demo.
It alarms on upward transition into levels Very high/Extreme, or an increase
in nearby detections. It lights LEDs, maps wildfire risk 0..100 to servo
0..180 degrees, displays OLED values, and posts DHT readings at POST_SECONDS.
It does not read the new hazards map. Additive `/api/beacon.hazards` should not
change its existing fields or assumptions.

Firmware security note:
  For HTTPS, the sketch calls WiFiClientSecure.setInsecure(), disabling server
  certificate verification. This is labeled a hackathon shortcut in source;
  production device work should replace it with certificate validation.
  STATION_TOKEN is optional server-side and example config defaults empty.

Example config note:
  firmware/pyrowatch_beacon/config.example.h contains sample ground station
  coordinates outside California. Out-of-state readings are accepted but have
  no California cell ID and do not attach to an in-scope risk area.

KNOWN ARCHITECTURE DEBT / SAFE NEXT WORK
----------------------------------------
These items describe current structure and candidate work. Do not apply without
a user task, but account for them when planning adjacent changes:

1. Complete multi-hazard contract coherently if requested:
   - decide/implement Tornado input source and hazard definition (none exists);
   - decide what "primary hazard" means when scores use different indices and
     have differing calibration/data availability;
   - expose primary_hazard in payload with deterministic missing/tie behavior;
   - store score and required source values; migrate old DBs with nullable,
     idempotent ALTERs; update named INSERT columns and downstream reads;
   - include wind in thunderstorm score only if an explicit defensible formula
     is selected; do not silently alter the existing CAPE-only index;
   - update UI selector, top lists, score details, official-warning caveats,
     AI context, API tests, model/evaluation docs, and device contract only
     where specified.
2. `frontend/app.js` is still one 918-line controller. hazards.js is a small
   focused extraction, not a true api/map/ui module split. If refactoring,
   first preserve global state/event flow and test live/replay/validation,
   satellite rendering and station polling together.
3. DB writes are daemon-thread, fire-and-forget with one serialized connection.
   Errors are logged but no durable retry queue or graceful drain exists.
4. Station database readings do not restore active station metadata/history
   after service restart.
5. HTTP health route reports process liveness only. It does not check DB,
   providers, forecast freshness, or model load status.
6. Forecast feature computation is synchronous on request and does work for
   all cells. First-run elevation data acquisition is large; expensive cold
   starts may delay API responses. Existing cache is process-local except for
   selected disk caches.
7. Dependency versions are lower bounds and not locked. The app has no
   frontend dependency/build system.
8. Fire detections and historic fire labels are satellite observations with
   false positives/label limitations; an index and old validation table must
   not be presented as precise ignition prediction.
